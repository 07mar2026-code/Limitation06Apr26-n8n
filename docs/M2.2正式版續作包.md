## 二、每次續作前的必要檢查

| 順序 | 必查項目 | 通過條件 | 不檢查的風險 |
|---|---|---|---|
| 1 | Git 工作樹與遠端 | 辨認既有未追蹤檔；HEAD 與 `origin/main` 差異明確 | 覆蓋使用者檔案、從舊版本修改或錯誤推送 |
| 2 | 正式 n8n 連線 | Online；不得顯示 Offline／Reconnecting／未知 | 畫面修改可能未保存，卻被誤認為正式狀態 |
| 3 | 正式工作流基線 | `Daily Shepherd` 為 `Published`；D4 為 `Deactivated` | 在未知版本上啟用歷史，造成正式流程回歸或資料外洩 |
| 4 | HMAC 雙服務設定 | n8n 與 task-runner 均存在相同名稱與同一秘密值 | Code 節點看不到金鑰，或兩服務產生不一致結果 |
| 5 | 服務重新啟動 | n8n、task-runner 均重新啟動後回到 `運作中 1/1` | Zeabur 已保存變數，但舊容器仍使用舊環境 |
| 6 | 隔離草稿執行 | 不再回傳 `MISSING_HMAC_KEY`；不輸出秘密值 | 未證明金鑰真的進入執行環境就修改正式流程 |
| 7 | Google Sheet 回讀 | 正確檔案、頁籤、7 欄、零真人資料 | 寫錯表、寫入舊表或使用含原始 LINE userId 的欄位 |
| 8 | 同意機制決策 | 明確定義同意、拒絕、撤回及刪除流程 | 沉默或使用 Bot 被錯當成同意，違反資料最小化 |
| 9 | 合成測試回歸 | A/B 隔離、30 天、10 筆、混入錯誤 ID、fail-closed 全 PASS | 隔離邏輯回歸後仍可能接入正式 webhook |
| 10 | 發布前安全掃描 | 驗證腳本、`git diff --check`、資安掃描全 PASS | Credential、Token、ID 或真人內容被提交或發布 |

任何一項狀態不明，都視為未通過；停止正式 n8n 寫入、發布、commit 與 push。發布前另須先由使用者決定既有未追蹤項目的歸屬；不得為了讓工作樹變乾淨而刪除、移動或擅自忽略。

## 三、下一個最小安全任務

由使用者自行產生一組新秘密，不把值貼入對話：

```bash
openssl rand -base64 32 | pbcopy
```

接著在 Zeabur 完成：

1. `n8n` 服務：更新 `PASTORAL_ID_HMAC_KEY`，貼上新值並儲存。
2. `task-runner` 服務：新增 `PASTORAL_ID_HMAC_KEY`，貼上同一個值並儲存。
3. 重新啟動 n8n，等待 `運作中 1/1`。
4. 重新啟動 task-runner，等待 `運作中 1/1`。
5. 不處理專案設定中的「需要處理／遷移至伺服器」；該提示與 HMAC 無關，屬獨立基礎架構遷移。

完成後才執行 n8n 草稿 `M2.2 資料隔離合成測試（草稿）`，只確認金鑰可用，不讀取或輸出秘密值。

## 四、HMAC 通過後的正式實作順序

```text
回讀 Git／GitHub
→ 確認 n8n Online
→ 回讀 Daily Shepherd Published、D4 Deactivated
→ 執行 HMAC 草稿檢查並確認不再 MISSING_HMAC_KEY
→ 回讀新 Google Sheet：7 欄、零真人資料
→ 建立明確同意／拒絕／撤回並刪除分支
→ 未同意路徑只做安全單輪回覆，不經 D3／D4
→ 已同意路徑以 HMAC-SHA256 產生內部 ID
→ D3 只寫去識別欄位
→ D4 以目前內部 ID 做服務端篩選
→ D5 逐筆重驗 ID；不同 ID 整批阻斷且不送模型
→ 套用 30 天期限、最多最近 10 筆
→ 只用合成資料完成正式隔離測試
→ 所有測試 PASS 後才啟用 D4
→ 保存、重新載入回讀、發布
→ 執行正式但不含個資的端到端測試
→ 更新續作文件與公開去敏 workflow
→ verify-m2.2-draft.sh
→ verify-workflows.sh
→ git diff --check
→ 資安掃描
→ commit
→ scripts/publish-verified.sh
→ 回讀 origin/main
```
