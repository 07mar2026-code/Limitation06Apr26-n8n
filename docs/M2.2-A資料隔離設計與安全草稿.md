# M2.2-A 資料隔離設計與安全草稿

更新日期：2026-10-07（Asia/Taipei）
狀態：**設計與本機驗證草稿；未修改、未發布 n8n**

## 一、本輪邊界

本文件只定義 M2.2 的安全契約與後續實作順序。正式工作流仍維持 M2.1 安全單輪模式，`D4. 讀取歷史對話紀錄` 必須保持 `Deactivated`。

本輪禁止：

- 啟用 D4 或發布 M2.2。
- 把 HMAC 金鑰寫入工作流、文件、Git 或 execution log。
- 讀取、複製或遷移舊 Sheet 的 LINE userId 與對話內容。
- 以單一測試帳號宣告資料隔離完成。

## 二、目前風險

| 項目 | 現況 | M2.2 要求 |
|---|---|---|
| 使用者識別 | D2 取得原始 LINE userId，D3 保存於「發送者」 | 僅允許短暫運算；持久層只能保存內部 ID |
| 時間格式 | 精確到小時 | 改為 UTC ISO 8601，另存刪除期限 |
| 保存同意 | 尚無同意閘門 | 未同意時不得寫入 D3 或讀取 D4 |
| D4 查詢 | 無使用者篩選 | 必須先以內部 ID 做服務端等值篩選 |
| 歷史範圍 | 無時間與筆數限制 | 僅最近 30 天、最多 10 筆 |
| D5 | 直接取最後一筆 | 驗證每筆內部 ID；不一致時阻斷並走固定 fallback |
| 舊資料 | 含原始識別碼 | 舊表隔離唯讀，不自動遷移至新表 |

## 三、內部 ID 規格

```text
internal_user_id = base64url(HMAC-SHA256(project_secret, line_user_id))
```

- `project_secret` 為本專案專用的隨機高強度秘密，不得跨專案共用。
- 秘密由使用者在 Zeabur／n8n 的受保護環境設定中輸入；工作流只引用環境變數名稱 `PASTORAL_ID_HMAC_KEY`。
- 禁止使用無金鑰的 SHA-256；LINE userId 的格式與空間有限，純雜湊可能被離線比對。
- 輸出採 base64url，版本欄固定為 `hmac-sha256-v1`，方便未來輪替。
- 原始 LINE userId 只能在單次 execution 記憶體內存在，不得傳入 D3、D4、D5、Google Sheets 或日誌欄位。

## 四、目標資料流

```text
D2. 整理本次訊息暫存欄位
→ D2.1. 產生內部使用者識別碼
→ D2.2. 檢查對話保存同意
   ├─ 未同意：D5.1. 建立單輪上下文 → D6
   └─ 已同意：D3. 儲存去識別訊息
              → D4. 依內部 ID 讀取歷史
              → D4.1. 限制 30 天與最近 10 筆
              → D5. 驗證並組合隔離上下文
              → D6
```

D2.1 輸出後只保留：`內部使用者ID`、`識別版本`、`問題內容`、`問題類型`、`建立時間`、`刪除期限`、`保存同意版本`。不得保留 `發送者` 或任何原始 userId 別名。

## 五、新資料表契約

新表僅接收同意後的新資料，不沿用含原始識別碼的舊表。

| 欄位 | 格式 | 規則 |
|---|---|---|
| `內部使用者ID` | base64url 字串 | HMAC-SHA256 輸出；不得為空 |
| `識別版本` | `hmac-sha256-v1` | 支援未來金鑰輪替 |
| `建立時間` | UTC ISO 8601 | 必須包含秒與時區 |
| `刪除期限` | UTC ISO 8601 | 建立時間加 30 天 |
| `問題內容` | 文字 | 僅在明確同意後保存 |
| `問題類型` | 白名單字串 | 不接受模型產生的任意欄位名稱 |
| `保存同意版本` | 版本字串 | 例如 `pastoral-history-v1` |

## 六、查詢與組合硬性規則

1. D4 的第一層查詢條件必須是 `內部使用者ID == 本次內部使用者ID`，不可先取得整張表再於 D5 篩選。
2. D4.1 僅接受 `建立時間 >= 現在減 30 天` 且 `刪除期限 > 現在` 的資料。
3. 依建立時間由舊到新排序，最多保留最近 10 筆。
4. D5 在組合前重新驗證每筆 `內部使用者ID`；任何一筆不一致即停止生成，不把歷史送入 D6，改走不暴露內部原因的固定 fallback。
5. D5 輸出不得包含內部 ID、同意版本或刪除期限，只能包含經過長度限制的對話上下文。
6. 查無歷史不是錯誤，應退回安全單輪回覆。

## 七、同意、保存與刪除

- 預設為未同意；沉默、使用 Bot 或加入好友都不代表同意保存對話。
- 同意畫面必須說明用途、保存 30 天、可撤回及可要求刪除。
- 撤回後立即停止新增與歷史讀取，並依內部 ID 執行刪除程序。
- 每日排程刪除 `刪除期限 <= 現在` 的資料；日誌只記錄時間、成功／失敗與筆數，不記錄 ID 或內容。
- 舊表維持隔離唯讀，待指定資料管理者核准後另行刪除；本輪不遷移。

## 八、角色權限

| 角色 | 權限 |
|---|---|
| n8n 執行帳號 | 僅新表必要的讀寫與刪除 |
| 指定資料管理者 | 處理撤回、刪除與稽核；不得把內容另行下載 |
| 一般同工／牧養同工 | 預設無 Google Sheet 直接存取權 |
| 開發與測試人員 | 僅使用合成資料，不接觸真人內容 |

## 九、正式實作前硬性閘門

- 使用者已在安全環境中建立 `PASTORAL_ID_HMAC_KEY`，但執行者不得讀取其值。
- 已建立不含舊資料的新 Sheet，欄位符合本文件第五節。
- 同意分支已完成，未同意路徑不經 D3／D4。
- D4 保持停用，直到合成雙使用者測試全部 PASS。
- 測試 A、B 交錯至少各三筆；A 的上下文不得出現 B，反之亦然。
- 測試 31 天前資料不被讀取、超過 10 筆只保留最近 10 筆。
- 模擬錯誤 ID 混入時，D5 必須阻斷且不進 D6。
- 全部證據以「功能／輸入／預期／實際／PASS 或 FAIL／時間」記錄。

## 十、下一輪最小實作順序

```text
確認 n8n Online 且 Published
→ 備份最新原始 workflow 至 .private/
→ 建立獨立測試工作流或未接 production webhook 的草稿
→ 使用者自行建立 PASTORAL_ID_HMAC_KEY
→ 先完成 D2.1，僅用合成 ID 驗證同輸入穩定、不同輸入不同、輸出不含原值
→ 完成同意分支與新 Sheet
→ 完成 D4 服務端 ID 篩選
→ 完成 D4.1 30 天／10 筆限制與 D5 二次阻斷
→ 雙使用者合成測試 PASS
→ 再決定是否接回正式工作流
```

任何 FAIL、Offline、Credential 狀態不明或原始 userId 出現在持久層，立即停止，不得 Publish、commit 或 push。
