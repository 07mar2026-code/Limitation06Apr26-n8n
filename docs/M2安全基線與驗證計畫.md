# M2 日常牧養聊天機器人：安全基線與驗證計畫

更新日期：2026-10-07（Asia/Taipei）
狀態：**M2.1 安全單輪模式、專用模型隔離及 D3 新 Sheet 修正已發布；真實 LINE 端到端驗證 PASS**

## 一、目標與定位

M2 提供溫暖、尊重、低壓力的日常關懷與靈修陪伴，定位為教會行政與牧養輔助工具，不取代牧者、心理師、醫師、社工、法律或財務專業人員。

完成前必須同時通過：內容安全、資料隔離、危機轉介、模型失敗 fallback、經文校準及三輪真人對話。

## 二、現有資料流

```text
LINE 非空白文字
→ D1. 分析使用者訊息
→ D2. 整理對話紀錄欄位
→ D3. 儲存使用者訊息
→ D4. 讀取歷史對話紀錄
→ D5. 組合對話上下文
→ D6. 生成牧養回覆
→ D7. 回覆 LINE 牧養訊息
```

共用元件：

- 改名前的 `D8. 牧養對話語言模型` 曾同時供 D1、D6 與活動回覆使用；現已改名為 `A3.1. 牧養對話語言模型`，並只供 A3 使用。
- `D9. 呼叫牧養工具流程` 作為 D6 的工具。
- D7 已使用命名 Credential，不含節點內明文 Authorization。

## 三、唯讀盤點結果

| 項目 | 實際現況 | 判定 |
|---|---|---|
| 入口分流 | 所有非空白文字進入牧養支線 | 需細分意圖與危機優先序 |
| D1 分類 | 只能輸出感情、財務、家庭 | 無法涵蓋代禱、靈修、行政、危機與未知 |
| 使用者識別 | 直接保存 LINE `userId` | 不符合資料最小化，需改為不可逆內部識別碼 |
| 訊息保存 | 保存問題全文 | 尚無同意、保存期限、刪除與敏感內容政策 |
| 歷史讀取 | D4 未見篩選條件；D5 取輸入最後一筆 | 可能跨使用者混用，列為 M2 阻斷風險 |
| 高風險內容 | 無危機辨識與人工轉介支線 | 不可上線 |
| 模型失敗 | 各節點使用預設失敗行為 | 無使用者可見 fallback，可能沉默 |
| 牧養提示詞 | 固定 200–500 字、必含經文及兩個問題 | 對簡短、行政或危機情境不合比例 |
| 經文治理 | 要求引用經文，但未指定版本與校閱流程 | 需牧者校閱與可追溯版本 |
| 財務內容 | 有不構成投資建議警語 | 仍須避免個人化財務指示與債務決策代替 |

## 四、M2 硬性安全閘門

以下任一項未完成，禁止 Publish、真人測試、commit 與 push：

1. 危機訊息必須先於一般 AI 分類，且不可送入一般生成流程。
2. 高風險回覆使用固定文字與人工轉介，不讓模型自行判斷急迫處置。
3. 歷史資料必須按單一使用者隔離，不可讀取其他會友訊息。
4. 不保存原始 LINE userId；改用不可逆、具專案 salt 的識別碼。
5. 明定對話內容保存期限、刪除方式、可存取角色與同意機制。
6. 模型、工具、Google Sheets 或 LINE Reply 失敗時，必須有不暴露內部錯誤的固定 fallback。
7. 經文版本、章節與上下文須可追溯，並經指定同工校閱。
8. 線上修改遵守「Online 才正式修改、Offline 僅唯讀檢查」。

## 五、建議分階段實作

### M2.1 安全入口

- 在一般牧養 AI 之前建立危機判斷。
- 建立固定危機回覆與人工轉介節點。
- 建立未知意圖與系統失敗 fallback。
- 驗證高風險輸入不會進入 D6。

### M2.2 資料隔離

- 將使用者識別改為不可逆內部 ID。
- D4 必須以該 ID 篩選，並限制筆數與時間範圍。
- D5 僅組合該使用者的近期紀錄。
- 設定保存期限、刪除程序與同工存取權限。
- M2.2-A 設計與安全契約已建立，詳見 [`M2.2-A資料隔離設計與安全草稿.md`](./M2.2-A資料隔離設計與安全草稿.md)；目前尚未修改或發布 n8n。

### M2.3 牧養回覆

- 分開一般關懷、代禱、靈修、行政與財務教育。
- 調整長度為依情境彈性回覆，不強迫每次引用經文或提出兩個問題。
- 經文採固定版本與出處格式，避免斷章取義或宣稱神諭。
- AI 回覆加入不診斷、不論斷、不施壓、不取代專業服務的邊界。

### M2.4 驗證與上線

- 先使用不含個資的模擬事件測試。
- 完成 20 案例，所有案例有功能／輸入／預期／實際／PASS 或 FAIL／時間。
- 高風險案例必須 100% 正確轉介。
- 牧者／指定同工完成內容校閱後，才進行三輪真人對話。
