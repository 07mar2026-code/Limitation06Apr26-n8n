# M2.2-C P0–P9 執行計劃

總計劃識別名稱：`M2.2-C-RELEASE-P0-P9-20261012`

## 一、共同安全閘門

- n8n 必須明確 Online，且能保存、關閉重開及回讀。
- 正式 `Daily Shepherd` 在受控修改前維持 Published；正式 D4 在候選版本完成前維持 Deactivated。
- n8n 與 task-runner 均須運作正常，且均存在同名 `PASTORAL_ID_HMAC_KEY`；不讀取、不顯示、不記錄金鑰值。
- 只使用去敏合成資料及匿名 LINE 測試資料；不得使用真人 LINE userId 或真人敏感內容。
- 不得混入其他內部 ID、跨教會資料、LINE 傳送、模型或 production webhook，除非該階段明確列入並完成獨立核准。
- 任一階段 FAIL 或狀態不明，停止後續階段、Publish、D4 正式啟用、commit 與 push。

## 三之一、真實 LINE 端到端成熟度安排

真實 LINE 端到端測試分成兩個不可互相取代的成熟度層：

1. **P5／上線前安全單輪成熟度**
   - D4 尚未啟用，正式 `Daily Shepherd` 維持 Published，正式 D4 維持 Deactivated。
   - 使用固定去敏訊息，確認 LINE webhook → 分流 → 模型 → LINE 回覆的完整鏈路。
   - 必須證明只回覆預期內容、沒有提示詞或內部錯誤外露、D4 未執行、沒有非預期 Sheet 寫入或 production webhook。
   - P5 PASS 只代表「D4 關閉時的真實 LINE 安全單輪」成熟，不代表歷史記憶功能可上線。

2. **P8／D4 啟用後功能成熟度**
   - 必須先完成 P6 受控啟用與 P7 D4 Active 驗證，才可執行。
   - 使用匿名、固定、去敏的 LINE 測試輸入，驗證歷史讀取、同意閘門、同一內部 ID 隔離、回覆送達、清理與最終資料狀態。
   - 必須同時回讀 n8n execution、LINE 實際回覆與 Google Sheet；任一證據缺失不得判定 PASS。
   - P8 PASS 才代表「D4 Active 的匿名 LINE 端到端」成熟；仍須等 P9 統一判定後才能 Publish 給真實使用者。

P5 與 P8 的共同停止條件：LINE 未送達或重複回覆、D4 狀態不符、模型／LINE／webhook 節點數異常、跨 ID／跨教會資料、提示詞或內部錯誤外露、Sheet 殘留或回讀不明、n8n 連線或憑證異常。

## 三、D4 啟用規則

1. P0–P5 未完成前，正式 D4 維持 Deactivated。
2. P6 只能在受控正式候選版本啟用 D4，不得直接把未驗證版本提供給真實使用者。
3. P6 啟用後若 P7 或 P8 任一 FAIL，立即停止，不得進入 P9 Publish。
4. P9 的「完成」定義包含 D4 已 Active 且 P7、P8 已 PASS；不能以文件 push 或合成壓測取代。

## 四、發布與 Git 邊界

- P9 前不得 Publish。
- 文件 commit／push 只代表文件保存，不代表 workflow 已發布。
- workflow Publish、正式 D4、真實 LINE 傳送、commit、push、遠端回讀分開記錄。
- 任何公開匯出不得加入 `.private/`、金鑰、credential、真人資料或敏感測試內容。

## 五、後續修改保留區

後續若需調整階段內容，保留原識別名稱並新增版本，例如：

`M2.2-C-P6-D4-CONTROLLED-ACTIVATION-v2-20261015`

不可刪除原 P6 證據；應在驗收紀錄的變更表寫明原因、影響範圍與替代條件。
