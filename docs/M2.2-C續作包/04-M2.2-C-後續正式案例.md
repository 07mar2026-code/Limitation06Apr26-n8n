## 四、撤回／刪除案例

固定 fixture：`synthetic-delete-fixture-20261010-v1`。

固定順序：

```text
使用完全相同的合成來源識別字串
→ 產生同一 HMAC 內部 ID
→ 刪除前精確回讀：保存同意 1、歷史對話 1
→ 輸入「撤回同意」或「刪除我的紀錄」
→ 回讀刪除 execution 已形成刪除請求
→ 刪除後依同一內部 ID 精確回讀：保存同意 0、歷史對話 0
```

沒有兩個頁籤的 0／0 證據，不得判定 PASS。整體頁籤總筆數不能取代同一內部 ID 的精確回讀。

## 五、30 天與最近 10 筆

- D4 第一層必須以本次內部 ID 做服務端等值查詢。
- 只接受 `建立時間 >= 現在減 30 天` 且 `刪除期限 > 現在`。
- 由舊到新排序，最多保留最近 10 筆。
- 任何必要欄位缺失、時間無法解析或內部 ID 不一致，整批阻斷。
- 查無歷史時退回安全單輪，不視為錯誤。

## 六、錯誤 ID 整批阻斷

- 合成回傳中只要混入一筆不同內部 ID，D5 必須固定輸出空歷史與 `sendToModel=false`。
- 不得只移除錯誤列後繼續使用其他歷史。
- 阻斷理由不得包含內部 ID、原始識別、訊息內容或秘密值。

## 七、compact 預覽與續期

### 第 27～30 天預覽

- 只在使用者主動傳訊時產生。
- 只讀同一內部 ID 最近 30 天、最多 10 筆。
- 預覽不得寫入 Google Sheet，也不得自動視為新一期同意。

### 精確續期指令

只有正規化後完整字串精確等於 `再保存30天`，而且原同意仍有效並位於第 27～30 天時，才可：

1. 重新依安全規則產生 compact 精華。
2. 保存一筆問題類型為「對話精華」的新紀錄。
3. 將同意到期時間延長 30 天。
4. 清除上一期原始歷史。

一般句子提到「再保存30天」不得觸發續期。原同意已過期、混入不同 ID、欄位畸形或時間無效時，整批阻斷，不保存、不送模型。
