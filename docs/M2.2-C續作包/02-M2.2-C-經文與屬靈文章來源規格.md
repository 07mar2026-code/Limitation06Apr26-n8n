# M2.2-C 經文與屬靈文章來源規格

更新時間：2026-10-10（Asia/Taipei）

狀態：本機模組與未發布 n8n 獨立測試鏈已驗證；尚未接入正式 LINE Bot。

## 一、最高原則與來源順序

經文正確性是最高原則。來源固定依下列順序判斷：

1. 已驗證且符合本次情境的經文白名單。
2. 同一教會、同一主題、人工核准且通過來源驗證的屬靈文章。
3. 省略屬靈引用，只提供一般牧養陪伴。

不得為了滿足格式、字數或「一定要有經文」而猜測內容。

## 二、經文白名單

目前只允許逐字使用下列內容，而且書卷與章節必須完全相符：

- 雅各書 1:19：「你們各人要快快地聽，慢慢地說，慢慢地動怒。」
- 腓立比書 2:4：「各人不要單顧自己的事，也要顧別人的事。」
- 哥林多前書 13:4：「愛是恆久忍耐，又有恩慈。」

禁止猜測、改寫、補全、拼接、重複或捏造經文。任一文字、書卷或章節不確定時，不得引用該經文。

## 三、屬靈文章輸出規格

只有同時符合以下條件才可使用：

- `churchId` 與本次教會完全一致。
- 文章與來源均為人工核准狀態。
- 主題符合本次情境。
- 正式網址屬於來源允許網域。
- 使用的是人工核准短摘錄，不是模型改寫或整篇全文。

最終回覆必須在同一自然段落完整包含：

- 明確標示「靈修文章」。
- 來源名稱。
- 文章標題。
- 完整正式網址。
- 逐字核准短摘錄。

可採自然句型：

> 這是一則靈修文章，來源：{來源名稱}，文章：〈{文章標題}〉，正式網址：{正式網址}。

缺少任一欄位時，不得引用文章；文章不得標示或暗示為經文。

## 四、教會資料隔離

- 每個來源與文章都必須有 `churchId`。
- 儲存層先以 `churchId` 做等值查詢，再逐筆驗證結果。
- 查詢結果只要混入其他教會內容，整批阻斷，不把任何屬靈內容送入模型。
- 不允許跨教會 fallback；本教會沒有相符內容時，只能省略。
- `approved_for_test` 在 production 模式不得使用。
- 新教會應使用自己的來源、允許網域、優先序與獨立 repository／資料分區。

## 五、母堂 Blogger 測試來源

| 欄位 | 設定 |
|---|---|
| `churchId` | `mother-church-test` |
| `sourceId` | `mother-blog-jamesjyan` |
| 顯示名稱 | 溪水旁默想園地 |
| 正式來源 | `https://jamesjyan.blogspot.com/` |
| 介接方式 | `blogger_manual_curated_v1` |
| 優先序 | `900`；數字越小越優先 |
| 自動匯入 | 關閉 |
| 測試文章 | 〈羨慕善工神的預備〉 |

此設定只核准測試 fixture 的標題、正式網址、主題與短摘錄，不代表整個部落格、所有文章或 production 使用已獲核准。

## 六、可替換來源設計

替換或新增教會來源時，只需：

1. 建立新的 `churchId`。
2. 設定該教會自己的 `sourceId`、顯示名稱、允許網域與數字優先序。
3. 將核准文章存入該教會獨立資料域。
4. 查詢時強制使用 `churchId` 等值條件。
5. 執行跨教會混入、未核准、錯誤網域及無可靠來源案例。

禁止先混合多間教會資料，再要求模型自行過濾。

## 七、FAIL 邊界

下列任一情形立即 FAIL：

- 經文錯置、重複、拼接、改寫、補全或捏造。
- 靈修文章被標示為經文。
- 缺少教會 ID、核准狀態、來源名稱、標題或正式網址。
- 網址不屬於允許網域。
- 查詢結果混入其他教會內容。
- 未核准或測試核准內容進入 production。
- 找不到可靠內容時仍生成、猜測或跨教會借用。

任一 FAIL：停止 n8n 接入、發布、commit 與 push。
