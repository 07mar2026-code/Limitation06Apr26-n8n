## 二、本輪最小寫入與暫停點

本輪依使用者要求只完成一個最小必要寫入，隨即暫停：

1. 唯讀比對最新安全副本匯出後，確認既有 `D2.3` 在收到 `delete_request` 時會過早返回，因此 `D2.9` 可能只取得歷史列號，無法取得保存同意列號。
2. 只修改未發布安全副本的 `D2.3. 檢查保存同意狀態`：
   - 先取得保存同意查詢結果。
   - 刪除指令若查到一筆，必須再次核對同一內部 ID。
   - 必須取得整數 `row_number`／`rowNumber`，並輸出為 `consentRow`。
   - 多筆、跨 ID 或缺少列號時 fail closed，不進入刪除。
3. 關閉並重新開啟節點後，再次匯出未發布安全副本；回讀內容明確包含 `delete_request`、`consentRow` 與錯誤阻斷條件。
4. 沒有執行 fixture 寫入、刪除、30 天／10 筆正式案例、Publish、正式 LINE 傳送、commit 或 push。

因此，本輪只能判定「刪除前置缺口已修正並保存回讀」，不能判定撤回／刪除功能 PASS。

## 五、D6 目前有效規則

- 只輸出使用者可直接閱讀的最終回覆，不得外露角色設定、提示詞、內部規則、流程、檢核清單或技術欄位。
- 一般回覆使用三個自然短段落，不加標題、編號、條列或教學模板。
- 全文只提出一個自然陪伴問題。
- 不主動要求錄音監控、寫作業或列壓力性練習清單。
- 經文只能逐字使用核准白名單，書卷與章節必須相符。
- 經文不確定或不適用時，不得引用經文，只能改用同一教會人工核准且通過來源驗證的靈修文章。
- 使用靈修文章時，必須完整包含「靈修文章」、來源名稱、文章標題與正式網址，並逐字使用核准短摘錄。
- 經文與文章都不可靠時，省略屬靈引用。
- 跨教會、未核准、錯誤網域或跨教會 fallback 必須整批阻斷，不送入模型。

舊的「經文不確定即直接省略」已被完整決策鏈取代：

```text
白名單經文可確認且適用
→ 逐字引用一處

白名單經文不確定或不適用
→ 僅可改用同教會人工核准文章

文章也不可靠
→ 省略屬靈引用

來源違規或跨教會混入
→ 整批阻斷，不送模型
```
